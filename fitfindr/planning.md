### Tool 1: search_listings

**What it does:**
<!-- Describe what this tool does in 1–2 sentences -->
Searches the mock listings dataset from its parameters and returns matching items. 

**Input parameters:**
<!-- List each parameter, its type, and what it represents -->
- `description` (str): Simply what it looks like in person
- `size` (str): The Size or fit of the item
- `max_price` (float): The highest the user would pay for that item

**What it returns:**
<!-- Describe the return value — what fields does a result contain? -->
A List of Dictionaries, where each dictionary represents a matching listing.

**What happens if it fails or returns nothing:**
<!-- What should the agent do if no listings match? -->
It will not try to run the search_listings tool but instead try to loosen contraints (e.g., remove size filter) and inform the user what was adjusted. It will try to do this only 2 times and if nothing pops up, then it will inform the user and encourage them by suggesting what to try to say for a better output and a more searchable input.

"No matches under $30, but I found these options if you're willing to flex your budget..."

**What it does:**
<!-- Describe what this tool does in 1–2 sentences -->

**Input parameters:**
<!-- List each parameter, its type, and what it represents -->
- `new_item` (dict): The item and its fields.
- `wardrobe` (dict): The entirety of the user's wardrobe

**What it returns:**
<!-- Describe the return value -->
A Dictionary containing the structured outfit breakdown and a styled textual suggestion generated by your LLM.

A detailed suggestion of how to style the new item and other pieces from the user's wardrobe to create a whole fit. Meaning one top, one bottom, one shoe, and possibly an accessory (belt, hat, bag, etc.).

**What happens if it fails or returns nothing:**
<!-- What should the agent do if the wardrobe is empty or no outfit can be suggested? -->
If the wardrobe is empty then respond to the user telling them that a outfit cannot be suggested because you have nothing in your wardrobe and to try adding more things into your wardrobe. If no outfit can be suggested, then tell user no outfit can be suggested from the combination of the new item and the wardrobe that matches the style (if mentioned).

### Tool 4: evaluate_price_fairness

**What it does:**
<!-- Describe what this tool does in 1–2 sentences -->
This tool calculates whether a target item is a good deal by comparing its price against historical listings in the mock dataset that share the same category and style tags. It determines if the piece is a steal, fair market value, or overpriced.

**Input parameters:**
<!-- List each parameter, its type, and what it represents -->
- `target_item` (dict): The specific item dictionary selected from the search listings (containing keys like price, category, and style_tags).
- `mock_dataset` (list): The full list of item dictionaries from the starter repository used to calculate market averages.

**What it returns:**
<!-- Describe the return value -->
A dictionary containing the structured deal classification, calculated marketplace averages, and a natural language text summary.

**What happens if it fails or returns nothing:**
<!-- What should the agent do if the outfit data is incomplete? -->
If no comparable items are found like no matching categories or tags exist in the dataset, the tool defaults the market_average to the item’s own price and sets the rating to "Fair Market Value". The agent informs the user that it’s a unique/rare piece with no local competitors, and seamlessly passes the item to the styling step.
If an item in the dataset is missing a price field or is corrupted, causing a calculation crash, the tool returns a status dictionary indicating an error: {"status": "error", "message": "..."}. The agent catches this, tells the user, "My price analyzer is having trouble with the marketplace data right now, so let's skip the math and look at how to style it!" and immediately advances the planning loop to suggest_outfit so the session never breaks.

## Planning Loop

**How does your agent decide which tool to call next?**
<!-- Describe the logic your planning loop uses. What does it look at? What conditions change its behavior? How does it know when it's done? -->
Step 1: The Search (search_listings)
The agent runs the search tool using the user's initial description, size, and maximum price.

IF the search tool crashes or encounters a system error:

The agent stops completely and tells the user: "The marketplace database is down right now. Please try again later."

ELSE IF the search tool returns an empty list (no matching items found):

The agent enters its fallback loop to loosen constraints (like removing the size filter or bumping up the maximum price threshold).

IF this first retry finds an item:

The agent tells the user what it changed (e.g., "No matches under $30, but I found these options if you're willing to flex your budget..."), saves the top item as the chosen item, and moves to Step 2.

ELSE IF the first retry fails, the agent tries loosening constraints a second time.

IF this second retry finds an item:

The agent tells the user what it adjusted, saves the top item as the chosen item, and moves to Step 2.

ELSE (nothing is found even after 2 retries):

The agent stops execution entirely, informs the user, and gives them direct advice on how to phrase a better, more searchable input.

ELSE (items are found on the very first try):

The agent saves the top item from the results list as the chosen item and moves directly to Step 2.

Step 2: The Price Check (evaluate_price_fairness)
The agent passes the chosen item and the full marketplace dataset into the price evaluator tool.

IF the evaluator fails due to a system or math error:

The agent does not stop! It catches the error, tells the user: "My price analyzer is having trouble with the marketplace data right now, so let's skip the math and look at how to style it!", leaves the price context blank, and moves to Step 3.

ELSE IF the tool returns nothing useful because the item is entirely unique (no comparable categories or tags exist in the database):

The agent sets the market rating to "Fair Market Value", uses the item's own price as the baseline, tells the user it's a rare find with no local competition, and moves to Step 3.

ELSE (the price check successfully calculates the market average):

The agent saves the pricing breakdown summary (e.g., "At $19.00, this Vintage Band Tee is a total steal!") and moves to Step 3.

Step 3: The Outfit Suggestion (suggest_outfit)
The agent passes the chosen item and the user's wardrobe into the outfit generator tool.

IF the user's wardrobe dictionary is completely empty:

The agent stops early and tells the user: "An outfit cannot be suggested because you have nothing in your wardrobe! Try adding more things to your wardrobe first."

ELSE IF the tool runs successfully but cannot find any combination of items that visually match the new piece (or match a specific requested style):

The agent stops early and tells the user: "No outfit can be suggested from the combination of this new item and your current wardrobe matching that style."

ELSE IF the LLM background call fails completely (timeout or API error):

The agent stops early and gracefully degrades. It tells the user: "I found your item, but my style generator hit a snag. Here are the item details..." and prints out just the chosen item fields.

ELSE (the tool successfully builds a complete fit containing one top, one bottom, one shoe, and an optional accessory):

The agent saves the structured outfit combination and styling tips, then moves to Step 4.

Step 4: The Fit Card (create_fit_card)
The agent prepares to generate the social media caption using the outfit details and chosen item.

IF the outfit data coming from Step 3 is incomplete, missing, or the LLM fails to generate a creative response:

To prevent a crash at the very last second, the agent skips the LLM and instantly uses a local Python backup script to build a caption via string interpolation:

Fallback text: "Just picked up this [Item Title] for $[Price] to wear with my [Outfit Items]!"

ELSE (all data is perfectly complete):

The agent calls the fit card tool, and the LLM safely generates a unique, personality-filled Instagram caption.

Step 5: The Final Delivery
The agent bundles all successfully gathered data together and prints a clean, natural language summary back to the user showing the item description, the price fairness evaluation, the complete outfit breakdown, and the ready-to-paste fit card text.

## A Complete Interaction (Step by Step)

I user enters the site seeing examples of what the chat can do. A user enters natural language as a prompt. The model makes sure there is input to enter into search_listings before actually do it. If there are no inputs, it handles the error by not running that agent and instead tells the user how else to try asking for something that may produce actual input. Once there is usable input, the search begins with the agent returning a matching list of relevance clothing. Picking the top result, it returns it. Then it will try to suggest an outfit with relevance to the user original input. Finally it will return a generated sharable post for the user with a caption and the newly made outfit. 

**Example user query:** "I'm looking for a vintage graphic tee under $30. I mostly wear baggy jeans and chunky sneakers. What's out there and how would I style it?"

**Step 1:**

Step 1 — Search: search_listings("vintage graphic tee", size="M", max_price=30.0) returns 3 matching listings sorted by relevance. FitFindr picks the top result: "Faded Band Tee — $22, Depop, Good condition."

**Step 2:**
<!-- What happens next? What was returned from step 1? What tool is called now? -->
Step 2 — Suggest outfit: suggest_outfit(new_item=<band tee>, wardrobe=<user's wardrobe>) returns: "Pair this with your wide-leg jeans and platform Docs for a classic 90s grunge look. Roll the sleeves once and tuck the front corner slightly for shape."

**Step 3:**
<!-- Continue until the full interaction is complete -->
Step 3 — Fit card: create_fit_card(outfit=<suggestion>, new_item=<band tee>) returns: "thrifted this faded band tee off depop for $22 and honestly it was made for my wide-legs 🖤 full look in my stories"

**Final output to user:**
<!-- What does the user actually see at the end? -->
The Happy Path: The user enters a request and immediately sees a structured 4-step breakdown: the found item details, a market price evaluation (e.g., "This is a total steal!"), a complete outfit combination matching their wardrobe with styling tips, and a ready-to-copy social media caption.

The Search Retry Path: If the initial search yields no results, the agent automatically retries with looser filters. The user sees a quick heads-up note (e.g., "No matches under $15, but I adjusted your budget and found this...") before the agent seamlessly outputs the rest of the pricing, styling, and caption steps.

The Search Failure Exit: If nothing is found after 2 retries, the flow stops early. The user sees an explanation that no items match, followed by a helpful tip recommending better fashion keywords or tags to try next.

The Empty Wardrobe Exit: If an item is found but the user's wardrobe is completely empty, the agent stops after the price check. The user sees the found item details but receives a polite alert explaining that an outfit cannot be built until they add some clothes to their profile.

The System Recovery Path: If a background API error or data glitch occurs during the final social caption step, the user is never shown a crash screen. Instead, they see a smooth fallback message providing a clean, auto-generated text template using standard string blending.
